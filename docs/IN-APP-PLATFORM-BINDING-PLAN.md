# 三平台App内绑定开发文档

## 目标与已确认选择
在iOS快递管家内绑定淘宝、拼多多、京东是整体目标。**当前执行范围按用户最新指示只做京东**：拼多多现有Cookie方式已可用且暂未发现顶号，本轮保持原样；淘宝不重做，不新增统一三平台账号页。先前取消时间比较的未提交修改必须保留。

## 参考与许可边界
- Parcly固定提交：0e4c7739205b368ab9bed3299f963a3e6fd9cf91。GPL-3.0；借鉴官方网页会话、登录验证、前台连接器和登录态健康保护，不直接移植受许可约束的Dart/JS实现。
- kdyzm固定提交：b13c0527cb38f3aad79cacf8ca85efacaa0004ed。自定义非商业许可；借鉴平台字段及分离登录/采集/物流结果的协议思想，不复制实现或把PC thor会话当手机pt_key等价物。
- Parcly pdd_web_screen.dart明确以内置商城替代官方App来避开双端互踢，不提供双端共存保证。kdyzm公开服务端接收已有Cookie，不证明免互踢登录能力。

## 范围
1. 设置页增加京东登录／订单导入入口，状态区分未保存、已保存会话、最近订单访问成功/失败，不把Cookie存在当完整成功。
2. 淘宝和拼多多保留原登录、Cookie、导入及查询行为，本轮不做内置商城、风险弹窗或互踢治理；共享Cookie新增字段只为京东保留安全属性，旧数据兼容。
3. 京东双入口：官方账号网页登录沿用独立Swift/WebKit移动网页连接器；手动Cookie导入与kdyzm一致接受包含thor的PC Cookie（不要求pin），使用独立Swift PC订单/物流协议读取，不假定thor与pt_key互通。入口名明确“账号网页登录”和“导入Cookie”；只含pt_key的手动Cookie不作为本轮支持入口，提示使用官方网页登录或完整PC Cookie。官方页是否提供账号密码/短信及风险验证由京东决定，App不保存账号密码、不自动发送短信。
   - PC协议按公开固定提交独立实现：api.m.jd.com/api的pcorder_center_list、pcdetail_traceMultiPackage；固定HTTPS主机、拒绝重定向，订单与运单双重身份校验，无h5st/设备签名仿造。
   - 每次当前第一页、最多8个详情、总预算30秒；单票仅目标订单及运单，20秒。不拓展全量历史同步、无码订单工作台、多账号或购物。
   - Cookie格式校验后先读取实际订单验证，再写独立Keychain；验证失败保留原会话。PC直连验证不使用WebKit上下文，避免错验为旧账号；保存成功才清除京东旧网页上下文。
   - 两条读取链路都保留安全详细诊断，不记录Cookie/完整请求URL/原始响应，不自动重试或改用付费渠道。
4. 统一importMall/refresh现有模型；已有backend binding保持后台路由，不隐式改绑；旧京东无后台的显式本机绑定后才使用京东直连。
5. 每个平台单独会话存储与域名白名单；凭据仅Keychain，Secure/HttpOnly属性保留，禁止明文降级、原Cookie日志/JS凭据桥。会话清除只影响本平台本机，不调用远端logout。
6. 限制每次读取与单票预算；取消/dismantle/onDisappear终止浏览任务；网络不持dataset flock。真实手机号/单号/响应不送搜索、不写fixtures。

## 验收
- 自动测试：会话与平台隔离、授权未验证不称成功、身份错配/未知结构拒绝、不请求收费fallback、取消/截止、风险提示、历史数据和取消时间比较不回退。
- 本机为Linux无Swift/Xcode：可执行源码契约与JS合成fixture，必须明确非Swift运行证据；新增XCTest交后续获授权CI执行。
- 真机验收需用户自行在官方页登录京东，分别验证登录后订单、真实运单详情、关闭重开及失效重登。本轮不触发拼多多重登；未实际通过不得声称京东可用。
