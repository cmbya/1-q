# 淘宝单平台试验开发说明

## 交付与边界
设置新增“淘宝导入（试验）”：在淘宝网页由用户登录，保存登录会话后手动读取待收货订单，预览完整运单、公司与商品标题，逐票确认导入现有快递。首版只查第一页、最多8个待收货订单，必须明示截断与失败，不宣称全量同步。淘宝订单号不是运单号，缺失运单不创建记录；多包裹不可只拿首票。不根据订单“待收货”伪造签收/取件状态，不自动UAPI查询。

## 架构
原生SwiftUI设置入口＋非持久WKWebView登录。登录会话仅保存本机Keychain独立服务，首次解锁后可访问，不存UserDefaults/JSON备份；无明文回退。退出清除会话和预览。网络只访问写死的淘宝HTTPS接口，Cookie按域、路径、Secure及到期过滤，不发给第三方，拒绝重定向。不在日志/错误输出原响应、Cookie、订单内容。验证码和二次验证由用户处理，风控/过期停止，无后台保活或自动反复重试。

MTop标准请求摘要基于CryptoKit MD5（协议兼容用途，不用于密码安全）。令牌过期最多一次引导与重试，只处理令牌刷新，不绕过登录或验证。返回新Cookie仅在本次内存会话使用，用户主动登录时才持久化。

待收货订单接口和运单接口按GitHub公开参考核对，属于非官方客户端接口，可能失效。参考Parcly了解移动端订单结构；不复制其GPL实现，Swift实现独立编写；接口机制辅助参考MIT项目dsh-parcel-tracker，其仓库版权声明保留在本文参考链接。无真实账号样本时不得宣称已成功读取淘宝订单。

## 数据保证
手动确认前不写快递；导入调用现有ShipmentStore.addThrowing，已有规范化单号跳过且不覆盖备注、状态、提醒、取件码和身份，历史重复不合并。共享存储只读时禁用导入。导入结果逐票报告新增、已存在、失败，预览仅内存，不保存原始响应。

## 验证
先写解析与域限制Swift测试；本地Linux无Swift/Xcode，不能运行真实XCTest，辅助模型/静态检查不冒充功能实测。完整编译需要后续用户授权；真实登录、验证码和接口可用性须在iPhone验收。当前授权不包含提交推送、Actions或真实购物账号访问。
