# UAPI 原生物流查询与快捷指令刷新

## 本轮实现范围
App 设置页配置 UAPI Key 与隐私同意；详情单票刷新、首页刷新未签收、添加后可保存并查询；快捷指令动作「刷新未签收快递物流」「刷新指定快递物流」。原先导出列表方案暂缓。

## 官方契约
GET https://uapis.cn/api/v1/misc/tracking/query
Authorization: Bearer <手机钥匙串中的密钥>
tracking_number 必填，carrier_code 仅使用独立保存的 UAPI 公司码，phone 可选4位尾号，refresh=true。
单次官方标价40积分；不匿名兜底，不自动重试计费请求。401/403、额度或429停止批量并汇总；遵守Retry-After，不在自动化中长时间等待。
响应使用 status_code/status/is_completed 与完整 tracks；明确冲突拒绝，unknown保留旧状态；最新轨迹时间不等于查询时间。Key和手机尾号不进入JSON备份；手机尾号本轮只作为本次操作参数。

## 数据与并发
沿用共享容器与原子事务。网络请求在锁外进行，落盘前再核实原记录ID及单号，删除不复活，已完成不回退，旧轨迹不覆盖新轨迹。刷新仅更新现有记录，保留备注、提醒、取件码、分组与身份。
新增可选 uapiCarrierCode、lastQueriedAt 与 lastQueryAttemptAt，兼容旧数据；尝试时间仅用于批量轮转，lastCheckedAt仍表示原手动查看时间。API结果直接保存，不经过AI或本地文本关键词重判。首次启用明确说明向UAPI发送单号/必要尾号，Key只存Keychain。

## 调用方式
1. 设置 → UAPI物流查询，保存Key并启用。
2. 单票详情刷新，必要时填写手机尾号；首页批量刷新仅运输中/派送中/待取件/异常。
3. 快捷指令个人自动化调用刷新动作；首次运行先手动授权，自动化没有应用二次写入确认。
4. 批量串行，单次请求15秒超时，每轮启动新请求的预算20秒；按最久未尝试优先轮转（旧记录回退到成功查询时间），独立保存尝试时间，不改动原物流或成功查询时间，跨 App/快捷指令执行保留进度。预算耗尽返回未处理数量，不承诺后台准点完成。单票超时、服务暂不可用或无数据继续后续票，不自动重试；认证、额度、限流、配置或钥匙串问题停止整批，取消立即停止。汇总返回成功/失败/新签收/未处理数量及失败单号和脱敏原因，不回显原始网络错误或凭据。

## 验证边界
本地Linux没有Swift/Xcode，本轮不提交推送、不触发CI、不调用真实账户。先编写XCTest再实现，但无法声称完成运行时RED/GREEN。用模拟网络与临时共享数据覆盖字段、密钥、失败、时间、删除并发、状态及重复码规则；真实账户、iOS锁屏/后台AppIntent与重签运行需后续授权验证。
