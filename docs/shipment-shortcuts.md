# 快递快捷指令（开发中，未编译验收）

## 动作
- 添加或更新快递：结构化单号、服务商、最新物流文字、状态和可选发生时间。
- 识别并添加或更新快递：一票快递的原文或以下 JSON；AI 开启时直接由 AI 识别，关闭时才由本地识别。AI 失败明确报错，不静默回退到本地。
- 添加取件码、识别并添加取件码：原有动作，各自新增“写入前确认”。

四个动作的“写入前确认”默认开启，关闭后不调用应用主动确认。iOS 系统授权提示不受此开关控制。歧义、无效单号、状态冲突仍不保存。

## minis 建议输出
```json
{
  "trackingNumber": "YT1234567890123",
  "carrierName": "圆通速递",
  "logisticsInfo": "本人签收",
  "status": "已签收",
  "logisticsTime": "2026-10-30T11:00:00+08:00"
}
```
时间缺失时省略，不使用查询时间冒充物流发生时间。无时区的 `yyyy-MM-dd HH:mm[:ss]` 按中国标准时间解释。

## 更新规则
- 单号只去首尾空白并转大写；混入链接、手机号或格式不符则拒绝，不修补坏单号。
- 同单号原地更新，保留记录ID、创建时间、备注、提醒、已有取件码及分组。缺省/空白可选字段不清空旧值。
- 最新物流字段只保存最新一条事件；详情页下方“本次查询完整信息”另存识别动作收到的原文（包含其已有历史轨迹和查询来源），不由 AI 改写，不额外联网补查。成功更新时替换该单号上次全文，不累积；没有传入全文的结构化更新不清空已有值。完整信息不参与状态推断。
- 明确用户已签收/已领取/已取件时标为已签收，关联取件码完成，其他取件码不受影响；驿站或快递柜代收不等于用户已领取。
- 首页批量识别仅接受能明确分票的独立行或空行分块；单号与状态/取件码归属不明时不生成草稿，避免串票。
- AI 返回的状态和最新事件由模型判断，本地不按关键词重判或选取另一条事件；仍检查字段格式、原文摘录、单号合法性及多票歧义。AI 语义判断可能出错，不把格式检查视为语义正确的证明。
- 最新物流信息只保存最新进展正文，不包含单号、公司、状态标签和查询来源。本地支持带标签的单行/多行查询文本；无法确定归属时不以全文兜底。最新时间为空不补查询时间；缺省字段仍按既有规则保留旧值，不自动清除旧物流时间。
- 待签收/未签收不判定已完成。早于已存物流时间的更新拒绝；已有时间的物流收到无时间物流更新时拒绝。已完成记录不会被未完成状态自动恢复。
- 日期和状态判断有冲突时不写入；不联网查物流。AI需已配置且开启，原文将发到该服务；仅接受原文可验证的字段，不允许AI选择多个包裹中的一个。
