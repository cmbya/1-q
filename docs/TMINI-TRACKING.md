# Tmini 独立付费物流渠道

## 设置与使用

1. 设置 → 物流查询 → **Tmini物流查询（付费）**。通过 SecureField 输入平台提供的调用密钥，保存后在本机 Keychain 回读验证；不会发送测试请求。
2. 阅读并同意付费 GET 与隐私说明后启用。密钥隔离于 UAPI，使用设备本地 Keychain，不进入普通偏好设置、JSON 备份或诊断日志。清除按钮删除并回读确认，且停用渠道。
3. 快递详情的默认查询渠道可选 **Tmini（付费查询）**，以后默认刷新（包括批量快捷指令）会使用该渠道；也可使用“仅本次使用Tmini付费刷新”，不改变默认值。
4. 现有“刷新指定快递物流”和“刷新未签收快递物流”快捷指令，查询渠道可显式选 **强制Tmini（付费查询）**。不传渠道仍沿用旧规则；“仅商城”不使用 Tmini 或 UAPI。强制 UAPI/Tmini 优先于后台绑定；默认后台绑定仍用后台。

启用不会替换旧票来源或旧自动规则。失败不会静默切换 UAPI/其他渠道，不自动重试。每次 query 只派发一次网络 GET；批量遇到密钥、余额/额度、限频或维护错误，本轮不再派发该渠道，其他渠道可继续。批量原有执行时间上限仍适用。

## 请求与费用隐私

依据 [接口文档](https://api.tmini.net/detail/2)：GET `/apis/autonumber`，Query 参数仅 `key` 和 `trackingNo`。客户端仅使用 `https://api.tmini.net/apis/autonumber`，不使用文档中的明文 HTTP，也不做 HTTP 降级或 ATS 例外。拒绝全部重定向，使用系统证书验证、ephemeral 会话、禁用 Cookie/缓存、15 秒超时、流式 2 MB 上限。

密钥在 URL Query 中（文档不支持把它改成 Authorization 或 POST）；HTTPS 不能隐藏平台及其代理可见的请求地址。因此不要分享真实请求 URL、抓包或平台访问日志。客户端仅返回本地固定错误文案，不保存底层错误、原始 JSON 或完整 URL。Key 不作为快捷指令参数。

按用户指定口径进行**本地调用记账**：每次派发单号查询记 4 积分，设置页显示累计次数、累计积分及首次/最近时间。重复查询重复记，批量逐票记；所有入口共用客户端记账。网络错误、平台拒绝、无轨迹及解析失败也记，配置/单号校验失败或派发前取消不记。无余额或测试请求，不复用 UAPI 积分。

这是本地估算，**不是平台账单或余额**。为避免失败漏记，网络调用前先持久化；记账后取消或进程退出的极窄窗口可能多记一次。平台可能不对失败请求收费。仅统计本设备此功能加入后的调用，不追溯旧调用，不含其他设备；更换或清除密钥不清零，不区分账户。

当前已选 App Group 的独立 `tmini-usage.json` 只保存次数与首次/最近时间，不保存密钥、单号或URL，不随业务 JSON 备份导入导出。独立 flock 与原子写保护 App/快捷指令并发计数，网络期间不持锁。文件缺失显示零；损坏不冒充零、不覆盖已有数据，记账失败阻止新的请求并停止该渠道。设置页进入、回前台或手动刷新读取统计，不联网。无清零按钮；卸载或切换共享容器不保证保留统计。

Tmini 请求不含手机尾号，服务分支也不读取或写入手机尾号；这只是客户端协议，不保证平台实际能返回任何特定快递或真实取件码。`getcode`、`address`、`onboxTime` 及柜机坐标仅作为查询说明，**不自动覆盖取件码、个人地址、备注、提醒或记录关联**。

## 接收与保存规则

- 必须严格为字符串 `code == "0000000000"`、数值 `data.serviceCode == 0` 且无 `errcode`。错误示例数值 `code: 0` 不是成功。
- `packageInfoList` 必须只有一个包裹，其完整单号必须精确相同；多包、错号和重复冲突拒绝。
- 所有实际轨迹节点必须有合法时间与非空内容；日期按 Asia/Shanghai 严格解析并 round-trip，实际时间排序，乱序仍选择最新。完整 operate 节点可参与排序；同一最新时间内容冲突拒绝。无实际轨迹不能成功。
- `signFlag: AUTOMATIC` 不视为签收。只分类最新实际中文事件；文档明确的 `TRANSPORT` 可映射运输中，未知状态且事件不明确时保留现状态。
- App 与 AppIntents 共用 TrackingRefreshService 的 lease、身份/关联验证、旧物流拒绝、完成保护和安全失败记录。查询期间密钥/启用配置变化会拒绝晚到结果，密钥/指纹不持久化到 JSON。

## 验证范围

先新增 `TminiTrackingTests.swift` 与 Python source-contract 辅助检查，辅助检查先 RED（客户端缺失、路由/UI 未接入）再 GREEN。Python 检查**不是 Swift XCTest 或编译结果**。

当前 Linux 环境无 Swift/Xcode，XCTest、Swift 编译、iOS Keychain 与 URLSession 重定向/超时实机测试待在本地 Apple 工具链运行。没有真实密钥、没有真实付费请求，没有 commit/push/CI。此前无密钥 HTTPS 探针仅确认认证错误路径可达，不代表付费成功路径验证。
