# 京东网页链路修复与商城状态映射

## 原因与范围
用户真机可在京东网页看到订单，但保存验证和读取都改用PC订单网关，导致网页登录成功仍被另一接口判失败。本轮将京东验证、订单导入及来源刷新统一为手机网页链路；拼多多保留已真机成功的Cookie直连。旧PC客户端仍保留，不自动作为失败重试，也不自动转付费UAPI。

## 约束
- 普通页面自己发起请求；不生成签名、不绕过验证码，遇挑战明确停止并请用户在可见登录页处理。
- 网页访问必须在App前台。快捷指令后台无法使用这一路线时明确报错，不伪称后台刷新能力。
- JSONP观察保留网页原回调；仅处理允许的京东接口，响应不输出到日志。
- Cookie仍仅本机Keychain；手工导入先在独立临时WebKit上下文验证，失败不替换旧会话，不拿旧账号状态替新Cookie验证。
- 京东接受票据thor/pt_key搭配pin/pt_pin/_pst，但必要Cookie存在不等于登录成功，必须实际读到合法订单响应。
- DOM后备必须绑定精确订单页和唯一真实运单；不能拿订单ID充运单，多运单歧义拒绝，不猜对应关系。
- 状态仅取最新带时间节点，完成取件与驿站暂存分开；否定、预计及条件语句不能判完成。已有终态/旧事件保护仍由刷新事务负责。

## 验证边界
Node可执行网页观察脚本回归；Swift/XCTest和Release通过现有GitHub Actions运行。本地没有Xcode。模拟器和产物校验不等于真实京东账号/设备可用；用户设备还需确认登录保存、订单导入及轨迹刷新。安装前备份，覆盖安装而非卸载。
