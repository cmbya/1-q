# 网络物流刷新：移除跨新旧时间拦截

## 当前行为

- `TrackingRefreshService` 的 UAPI、Tmini、淘宝与商城共用结果合并路径，不再比较返回物流时间与本地 `logisticsTime`，也不再比较返回查询时间与本地 `lastQueriedAt`。快捷指令触发网络刷新同样走此路径。
- `KDYZMMerger` 同步快照与后台刷新不再比较远端更新时间、本地缓存更新时间、远端事件时间与本地事件时间；同时间不同文字也使用本次返回。主节点只从本次返回中选取，历史 `backendEvents` 仍保留。
- 后台完成任务不再要求 `logisticsCheckedAt` / `logisticsUpdatedAt` 大于等于 `job.createdAt`，也不要求存在非零任务创建时间。字段格式验证仍保留。
- 状态使用本次有效结果；后台 `transit` 可以替换本地待取件状态。已签收不可倒退、归档保护与手动取件完成保护保持原有语义。

因此，本次请求结果可以早于已保存记录；不保证上游返回的是最新数据。对单次返回内部事件排序属于主节点展示与状态解释，并非跨新旧拦截。

## 未移除的保障与范围边界

身份、运单号、订单、授权、credential/configuration generation、lease、任务 ID、取消、空轨迹/失败结果保护、执行预算、重试节奏、限流和不自动切换付费渠道均保留。诊断枚举历史值保留兼容。

`ShipmentShortcutService` 原始文字导入同样取消较早时间和无日期输入拦截。替换无日期物流时清空上一事件的日期，避免旧日期挂在新文字上；只修改承运商等非物流字段仍保留原事件时间。历史付费缓存兼容代码及用量记账的时序保护不属于物流结果合并；在线刷新仍不读取历史付费缓存。
