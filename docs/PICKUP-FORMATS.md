# 取件／取餐文字格式兼容

## 核实的依据与不确定范围
- 丰巢官网 https://fcbox.com/pages/product/use.html 介绍短信、微信、支付宝通知后输码，以及一键开柜。官网该页面没有公布统一码长。
- 用户提供的通知包含 `取件码 (98522212)`，为本轮精确回归输入，不将它的真实码上传搜索。
- 欢猫智柜开发者版本说明 https://apps.apple.com/cn/app/id6745598615 明确有“取件码强制改6位数”，说明柜机不能全部限定8位。
- 极目新闻经凤凰网转载 https://news.ifeng.com/c/8vzGiwPXoVw 引述瑞幸客服：取餐码最多三位，最高999。不能把奶茶咖啡一律限定6/8位。
- 喜茶“取茶号／取餐编号”、菜鸟 `z-y-xxxx` 形式有公开用户实例，只作为格式参考，不冒充全国统一官方编码标准。
- 联网实际引擎DGO与SGO；没有依据宣称覆盖所有品牌或任意OCR输入。

## 统一兼容
明确取件码／号、取货码／号、提货码／号、取餐码／号、取茶码／号、取咖啡码／号、自取码／号、取餐编号标签，含对应繁体。允许标签后空格、换行、是／为、冒号及已有连字符分隔。
码可保留前导零、字母大小写、现有允许符号与完整分段；纯数字餐号如7、01、001需要明确标签，不凭数字长度或品牌猜码。
支持成对()、（）、[]、【】、「」、『』，只去除外包装，不拼合、不截断。未闭合、错配、闭括号后紧接标识符不自动保存。原来【取件码-3-4-1366】整段外框继续可用。
本地取件提取、AI返回值的标签／包装／多码保护、快递智能粘贴入口共享标签与安全规则；快递智能粘贴仍需运单和待取件状态，保留其原有码长限制，不作为饮品导入入口。AI开启仍原文直交AI、失败不回退本地，不用本地候选替代AI语义。
包裹数量、手机号、订单号、运单号、验证码、URL维持保护；对带括号与新餐号标签的这些字段也保护。一个标签后多个独立码（包含分别带括号的列表）是歧义，不能选首码自动保存；不同通知不按相同码合并。
地点只提取原文明示内容：用户丰巢例应为“丰巢快递柜”，无分店地址不虚构。QR码、手机号认证、开柜链接、无标签纯数字页面不冒充文字码支持；需可靠AI上下文或手动处理，不自动改O/0、I/1。

## 验证
新增本地、AI模拟、快捷指令持久化和智能粘贴回归；Linux系统ICU流程／安全模型共330项断言通过，包含原始丰巢通知及地点、菜鸟整段码、短餐号、成对包装、多码与字段保护。辅助模型不是Swift执行，也不是330项XCTest。当前没有Swift/Xcode，新增XCTest与Release未运行，未调用真实模型、未推送构建。既有自定义提示词不会被覆盖，新默认提示词需用户选择恢复默认才替换自定义内容。
