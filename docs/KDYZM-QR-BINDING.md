# 后台二维码绑定

协议固定参考 `zsdd2/kdyzm` commit `b13c0527cb38f3aad79cacf8ca85efacaa0004ed`：`src/service.mjs:147` 的原始 JSON `{schemaVersion:1,baseUrl,code}`；`src/store.mjs:215` 的绑定码是 16 位大写十六进制。不是自定义 URL scheme。

入口：设置 → 取件助手后台 → 扫描后台绑定二维码。相机识别后仅在当前界面内存填入 HTTPS origin 和绑定码，不自动打开 URL、不联网、不记录或持久化二维码。也保留手动地址／绑定码备用。

安全确认分两步：
1. 阅读目标 origin，点击「确认地址并预检」才向该 origin 发送绑定码。二维码不能证明地址属于可信管理员，请先核对地址和端口。
2. 阅读预检返回的全部平台账号／家人组、未来账号授权及有效期，再点击「确认授权并绑定」。预检不消耗绑定码；最后一步才兑换。

编辑任一输入、重新扫码、离开界面或切换只读历史快照都会使原预检失效。已绑定设备必须先明确解绑，不能用新扫码覆盖。取消扫描不访问后台、不消费绑定码。相机在后台暂停、回前台恢复；关闭时串行停止和移除输入输出；权限回调使用弱引用且受关闭状态保护。多二维码／非法 JSON 只报固定错误并停止当前扫描，请取消重试。拒绝相机权限或设备无相机时可取消并手动填写。照片识别未加入本次范围。

配置以 `project.yml` 的主应用 `info.properties.NSCameraUsageDescription` 为权威；Info.plist 由 XcodeGen 生成，不另创建源 plist。新 Swift 文件由目录 sources 自动纳入。

验证：新增 Python 源码契约先红后绿；新增 `KDYZMPairingTests.swift` 覆盖官方 JSON、HTTPS origin、schema 布尔／字符串／小数、码格式、缺失／额外／错误类型字段、超长输入及多个二维码。源码契约不是 Swift 编译或相机实测。

必须在 macOS/Xcode 执行 XCTest 和应用编译；真机检查首次允许／拒绝／系统限制、取消等待授权、连续识别单次回调、多个二维码、切后台／锁屏／返回、关闭重开、无相机／运行中断，以及完整「扫码→地址确认→范围预检→授权兑换」流程。兑换已发送后取消网络并不保证后台回滚，重新打开页面应以钥匙串实际状态为准，不盲目重用旧码。
