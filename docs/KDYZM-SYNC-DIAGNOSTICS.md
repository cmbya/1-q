# 后台快照兼容与安全诊断修复（本地未发布）

## 已证实的兼容缺陷

上游 zsdd2/kdyzm 固定提交 b13c0527cb38f3aad79cacf8ca85efacaa0004ed 的 src/store.mjs 以账号、订单、承运商和单号区分运单。客户端原先在快照校验中按账号、承运商、单号拒绝重复，导致不同订单合并发货的合法快照被整体拒绝。

修复仅在校验身份中加入 orderId。仍拒绝重复 shipment ID、同一订单同承运商同号重复、跨账号/家人越权及缺失订单关联。导入按 origin/account/order/shipment 完整绑定分别保存，重复同步保持 UUID。不按单号全局合并。存在未绑定本地同号票时仍拒绝有歧义的自动关联；相同取件码冲突保护也仍保留，不借此修复放宽业务唯一性。

## 固定阶段提示

- SYNC-DECODE：快照缺字段、类型不符或 JSON 解码失败。
- SYNC-VALIDATE：快照身份、关联、字段校验失败。明确越权仍显示原无授权提示。
- SYNC-LINK：导入合并过程的关联冲突，事务不保存。
- SYNC-READ：读取原本地数据失败。
- SYNC-WRITE：本地事务校验或保存失败。
- SYNC-DISPLAY：同步事务已保存，但重新读取界面失败；不能描述为“没有修改数据”。

401/403、密钥变化、迟到结果及取消仍保留原语义。诊断只包含静态枚举与固定中文，UI通过原有安全错误显示路径展示，不新建原始响应日志，也不保存字段路径、Token、单号、商品、地址或底层错误。网络/HTTP/大小上限仍沿用原安全错误；本轮不修改后台或请求真实账户。
