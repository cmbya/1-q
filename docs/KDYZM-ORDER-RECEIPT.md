# 后台待发货订单与送达确认

本次只补充后台快照中的无运单订单展示和送达确认，不启用淘宝、拼多多直接导入。

## 待发货 / 无运单订单

进入“设置 → 取件助手后台”，点击“同步后台快照”。在“快递”首页的“进行中”或“全部”筛选中，可以看到“待发货 / 无运单订单”卡片，显示商品、平台、订单号以及待发货或暂无运单状态。

无运单订单单独保存在共享数据中，不生成虚构单号或取件记录，也不调用 UAPI、Tmini 查询。后台提供单号后，再次同步会移除对应无运单卡片，生成正常快递；一个订单有多个运单时仍分别保留。

已关闭、已完成、已签收、未付款、退款成功、已归档、已隐藏、已删除以及后台标明外卖配送的订单不会作为新的无运单卡片出现。后台未提供交易状态时只显示“暂无运单号”，不推断为待发货。部分快照中缺席的记录继续保留，明确的删除或隐藏标记才移除对应卡片。商品标题、身份和授权在无运单场景同样校验。

## 送达待确认

后台成功返回的最新有时间物流证明包裹已放在家门口、门前、家中，或无有效取件点与取件码的签收 / 妥投信息时，显示“已送达 · 待确认收到”，保留在“进行中”列表及未完成快递组件中。

打开快递详情，在“送达确认”里点击“确认收到”；确认后进入已签收列表。再次打开详情，可以“撤销确认，恢复待确认”。两种操作都保存在本机共享数据中，后续快照同步保留手动选择，不会操作商城平台的“确认收货”。

送到驿站门口、快递柜、门卫、前台等代收地点不视为送达家中；预计、未送达、投递失败、退回和预约请求不作为送达证据。历史取件码保留，但送达家中的包裹不再出现在待取码列表和取件码组件中。后台明确已领取证据继续沿用已有的自动完成逻辑。

新增字段均为可选，旧共享数据和备份可继续读取；无运单订单参与备份导出及冲突确认，按“保留现有 / 替换现有”策略合并。

## 验证范围

新增 KDYZMOrderReceiptTests 覆盖无运单重复同步、获得单号、拆包、过滤、授权、送达误判、确认撤销、旧数据和备份冲突。此次按要求不编译、不运行 XCTest、不生成 IPA，也不触发 GitHub Actions。源码和提取的文本规则另做静态检查；实际 iOS 行为仍需之后构建验证。
