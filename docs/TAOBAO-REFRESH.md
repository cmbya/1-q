# 淘宝物流与来源刷新开发约定

## 本轮范围
只接淘宝。保留原UAPI、记录身份、提醒、备注、取件码、共享存储、组件和快捷指令兼容。用户已授权推送main及正常Actions测试/Release/IPA发布；不得真实账号登录或执行付费查询。

## 数据与路由
- 每票分别保存可选添加来源、默认查询渠道覆盖、淘宝订单关联、当前物流来源；旧JSON缺失字段仍按原UAPI处理。
- 淘宝绑定必须包含有效订单号；多包裹按运单号精确匹配，歧义拒绝，不能以订单号代替运单号。
- 重新预览并确认导入时可补绑已有唯一记录；不得覆盖备注、取件码、提醒、ID或时间。冲突绑定明确拒绝。
- 默认按来源刷新；手动/UAPI旧记录沿用UAPI。允许单次UAPI备用和每票明确设为UAPI。淘宝失败从不自动收费回退。
- 单票、首页批量、两个旧快捷指令及选择快递动作共用路由。支持仅商城和强制UAPI，保留空尾号复用语义。

## 物流
使用明确结构的淘宝轨迹响应，必要时请求正常SSR详情页；不得执行页面脚本或放开重定向。核对运单号再保存。
最新节点、时间、状态、轨迹和来源入库；缺字段不杜撰。失败保留旧数据并显示失败及上次成功时间。历史状态与完成保护保持。
批量有时间预算、逐票结果，淘宝登录/验证失败停止后续淘宝请求，不影响其他独立渠道且不自动切渠道。

## 验证
先写回归测试，GitHub Actions运行Swift测试；本机Linux无Swift/Xcode且Docker无权限，源码检查不当作Swift测试。真实淘宝会话和网页可用性最终需用户手机验收。测试、Release、IPA和下载校验完成才交付包。
